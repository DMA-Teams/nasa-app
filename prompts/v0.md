# v0 de Vercel (Nivel 3: app en Next.js con link público)

v0 genera apps en **Next.js + Tailwind + shadcn/ui** y las despliega en Vercel con un clic. Ideal si alguien del equipo entiende un poco de código: lo que genera es un proyecto real que luego puedes abrir con Claude Code o Codex.

## Antes de empezar

- En las instrucciones del proyecto (si tu plan las ofrece) pega las reglas de `prompts/lovable.md` → "Reglas del proyecto".
- Ten a mano el **CSS de tu tema**: `design-tokens/build/<tema>.css`. Usa las mismas variables que shadcn/ui, así que v0 lo aplica directo.

## Prompt inicial

```
Crea una app en Next.js (App Router) con TypeScript, Tailwind CSS v4 y shadcn/ui para el
NASA Space Apps Challenge 2026, reto "[nombre del reto]". Interfaz en español, primero celular.

Propuesta de valor: "Ayudamos a [usuario] a [resultado] sin [dolor]".
Usuario: [persona concreta y lugar].

Datos NASA:
- Crea app/api/nasa/route.ts que llame a [URL exacta del endpoint] desde el servidor,
  con cache de 1 hora (fetch con next: { revalidate: 3600 }).
- Si la llamada falla, devuelve los datos de public/fallback/nasa.json con "fallback": true.
- Forma de la respuesta: [describe el JSON o pega un ejemplo corto].
- Las claves de API van en variables de entorno sin prefijo NEXT_PUBLIC_.

Páginas (solo el camino feliz, sin login):
1. "/" Entrada: [qué ingresa el usuario].
2. "/datos" Datos NASA: [gráfica con Recharts / mapa con react-leaflet] + "Fuente: [dataset], NASA · [fecha]".
3. "/resultado" Resultado: [indicador grande + explicación]. Regla: [regla simple].
4. "/accion" Acción: [botón principal (simulado)].

Sistema visual: reemplaza las variables de color de app/globals.css por exactamente estas:
[PEGA AQUÍ EL CONTENIDO DE design-tokens/build/<tema>.css]
Usa las fuentes indicadas en el comentario de ese CSS con next/font.
```

Si el CSS es muy largo para tu prompt, pega el bloque de `<tema>.prompt.md` y después usa el prompt de iteración 1.

## Prompts de iteración (uno a la vez)

1. **Tokens exactos:** `Reemplaza el :root y el @theme inline de globals.css por este CSS sin cambiar nada: [pega <tema>.css].`
2. **Datos visibles:** `En /datos muestra debajo de la gráfica el nombre del dataset, el rango de fechas y "datos de respaldo" cuando fallback sea true.`
3. **Celular:** `Revisa en 375 px: sin scroll horizontal, botones de 44 px, gráficas que se adapten al ancho.`
4. **Accesibilidad:** `Agrega foco visible, aria-labels en botones con ícono, texto alternativo en gráficas y respeta prefers-reduced-motion.`
5. **Demo en 1 clic:** `Agrega en "/" un botón "Ver ejemplo" que precargue [caso del pitch] y lleve a /datos.`

## Publicar y seguir con código

1. **Deploy** desde v0 a Vercel. Agrega las variables de entorno (por ejemplo `FIRMS_MAP_KEY`) en el proyecto de Vercel.
2. Descarga el código o conéctalo a GitHub; ábrelo con **Claude Code** o **Codex** dentro de este repo para pulirlo con las skills de UI (ver `docs/ui-skills.md`).
3. Prueba el link en incógnito y en el celular antes del pitch.

## Si algo sale mal

- Error de build en Vercel: copia el mensaje exacto a v0: `El build falla con este error: [error]. Corrígelo sin cambiar el diseño.`
- Cambió el diseño al arreglar algo: `Mantén exactamente los estilos actuales; solo corrige [problema].`
- Gráficas vacías: revisa que la API devuelva datos (abre /api/nasa en el navegador) y que se filtren los -999.
